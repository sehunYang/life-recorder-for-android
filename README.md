# Life Recorder

하루를 통째로 기록해 **Google Drive에 쌓아 두는 안드로이드 앱.**
ON을 누르면 백그라운드에서 **주변 소리(마이크)** 와 **화면**을 계속 기록하고,
정각마다 파일을 끊어 자동으로 올린다. OFF를 누르기 전까지 멈추지 않도록 설계했다.

나중에 검색·요약·회상이 가능한 **개인 아카이브의 수집 계층**을 목표로 한다.
모으기만 하고 해석하지 않는다. 합치고 복원하는 일은 내려받은 원본을 처리할 때 한다.

만든 사람이 자기 폰에 쓰려고 만들었지만, 누구나 그대로 빌드해 쓸 수 있게 정리해 두었다.
서버도 계정도 필요 없고, 데이터는 **본인의 Google Drive에만** 올라간다.
개발자를 포함해 제3자에게 전송되는 것은 없다.

컴퓨터 화면도 같이 남기고 싶으면 [Life Recorder for Windows](https://github.com/sehunYang/life-recorder-for-windows)를
쓴다. **같은 Drive 폴더**로 올라가고 파일 이름 접두어(`pcscreen_`)로만 갈린다. DESIGN.md 2.3 참고.

---

## ⚠️ 먼저 읽을 것 — 법적·윤리적 경계

이 앱은 **주변 소리를 상시 녹음한다.** 그 자리에 있는 다른 사람의 대화가 함께 녹음된다.
카카오톡 알림·문자·통화 녹음도 마찬가지로 **상대방의 발화가 들어온다.**

- **대한민국**: 「통신비밀보호법」상 자신이 참여하지 않은 **타인 간의 대화를 녹음하는 것은 형사처벌 대상**이다.
  본인이 참여한 대화의 녹음은 원칙적으로 허용되지만, 상시 녹음은 참여하지 않은 대화까지
  담기 쉽다는 점을 반드시 인지할 것.
- **다른 나라**: 통화·대화 녹음에 **모든 당사자의 동의**를 요구하는 곳이 많다(미국 일부 주, 독일 등).
  거주 지역의 법을 직접 확인할 것.
- 직장·학교·의료기관 등 **녹음이 금지된 공간**이 있다.

이 저장소는 코드를 제공할 뿐이고, **사용에 따른 법적 책임은 전적으로 사용자에게 있다**(LICENSE 참고).
녹음된 파일에는 본인뿐 아니라 **동의하지 않은 타인의 음성·이름·전화번호·사진**이 들어간다는 점을
전제로, 보관 범위와 기간을 스스로 정할 것.

## 무엇을 어떻게 모으는가

| 항목 | 방식 |
|---|---|
| 소리 | 마이크(CAMCORDER 소스, 마이크 두 개) → 앱이 직접 AAC-LC 48kHz 스테레오 256kbps로 인코딩. 음성 인식용 소스보다 먼 목소리가 훨씬 잘 남는다(3m 실측 말소리 대 잡음 17→38dB, 삼성 녹음 앱 32dB). MediaRecorder를 쓰지 않아 CPU도 약 40% 적다. 녹음 중엔 `.aac.part`(ADTS)로 써서 프로세스가 죽어도 그 시점까지 살아남고, 세그먼트가 끝나면 `.m4a`로 remux |
| 화면 | MediaProjection → H.264, 해상도 1/2(약 540px 폭), 최대 5fps, 0.8Mbps 상한. 앱 UI 글씨(상품명·가격·메뉴)는 비전 모델이 읽는 수준으로 실측 확인. 빽빽한 긴 글은 미검증 (발열 때문에 낮춤, `Config.SCREEN_SCALE`). 정지 화면일 땐 용량이 거의 안 늘어남 |
| 분할 | 벽시계 정각(HH:00:00) 기준. 첫 세그먼트만 짧고 이후는 1시간 단위. 화면 녹화는 키프레임에서 끊어 프레임 손실 없음 |
| 업로드 | WorkManager + Drive 재개 가능 업로드(8MB 청크). 크기/MD5 검증 후 로컬 삭제. 기본 Wi-Fi 전용 + 충전 중에만 (수동 "지금 업로드"는 즉시) 단 글자 자료(카톡·화면 글자·앱 사용·문자)는 **모바일 데이터로도** 올린다 (v0.8.1~, 설정에서 끌 수 있다) |
| 생존 | 포그라운드 서비스(마이크+화면캡처 타입) + START_STICKY + 배터리 최적화 제외 |
| 절전 | 화면이 꺼지면 화면 캡처 입력을 끊어 GPU 합성/인코딩을 멈춤 (소리는 계속). WakeLock 없음. 정지 화면 반복 프레임 10초. 발열로 끊는 기능은 없음 — 무거운 앱마다 기록이 멈춰서 뺐다 |
| 통화 녹음 | 업로드 작업이 돌 때마다 폰이 이미 만들어 둔 통화 녹음 폴더에서 새 파일을 찾아 앱 폴더로 복사 후 `LifeRecorder/call`에 업로드. **원본은 절대 지우지 않음.** 가져온 파일은 MediaStore ID로 기억해 중복 방지. 오디오 읽기 권한 필요 |
| 수집 기록 | 업로드한 파일을 하루치 JSONL(`index_yyyy-MM-dd.jsonl`)로 `LifeRecorder/index`에 남긴다. 기능을 넣기 전에 이미 올라가 있던 것은 `index_snapshot_<시각>.jsonl`에 한 번 훑어 남긴다. 보관 기간이 지나 원본을 지워도 무엇이 언제 수집됐는지는 남는다. 앱을 다시 깔면 이 기록을 읽어 "이미 올린 것"을 되살리므로 소급분이 다시 올라가지 않는다 |
| 카메라 | `DCIM/Camera`의 사진·동영상을 복사해 `LifeRecorder/camera`에 업로드. **원본은 절대 지우지 않음.** 사진첩이 크면 한 번에 다 올리지 않고 실행당 1GB씩, 최신 것부터 나눠 올린다 (`Config.CAMERA_BUDGET_BYTES`). 스크린샷은 제외. 기본 꺼짐 |
| 카카오톡 | 알림에 뜬 내용을 그대로 한 시간 조각 JSONL(`kakao_yyyy-MM-dd_hHH.jsonl`, v0.8~. 전에는 하루치)로 쌓아 `LifeRecorder/kakao`에 업로드. 해석하거나 합치지 않는다. "대화 내용 내보내기" 파일을 앱에 공유하면 그 파일도 원본 그대로 올린다 |
| 문자 | 어제까지의 SMS/MMS를 하루 단위 JSONL(`sms_yyyy-MM-dd.jsonl`)로 그대로 내보내 `LifeRecorder/sms`에 업로드. 시각순 한 줄에 하나. 처음 켜면 30일치를 소급. RCS 채팅은 제외(시스템이 제3자 앱에 열어주지 않음) |
| 화면 글자 | 접근성 서비스가 **앞에 떠 있는 앱의 화면에 보이는 글자**를 뷰 계층에서 그대로 읽어 한 시간 조각 JSONL(`screentext_yyyy-MM-dd_hHH.jsonl`)로 `LifeRecorder/screen-text`에 업로드. 앱을 가리지 않는다 — 카카오톡이면 알림에 없는 내 발화·그룹방 이름이, 다른 앱이면 문서·게시글이 OCR 없이 온다. 비밀번호 입력란과 이 앱 자신만 뺀다. 설정 > 접근성에서 직접 켜야 한다 |
| 비공개 앱 | **Brave**가 화면에 떠 있거나, **최근 앱 화면에 Brave 카드**가 보이거나, **Chrome 시크릿 탭**이 보이는 동안은 화면 녹화 입력을 끊고 화면 글자도 남기지 않는다. 판정은 창이 뜬 뒤에야 되므로 화면 프레임을 1.5초 붙들었다가 쓰고, 판정되면 그 앞 1초의 프레임을 버린다(여는 애니메이션). 영상에는 그 사이가 빠진다. 앱 사용 기록에서도 Brave는 전부, Chrome은 시크릿 구간의 사건을 뺀다. 판정은 접근성 서비스가 하므로 그것이 꺼져 있으면 가리지 못한다. Chrome 시크릿 웹 페이지에는 접근성으로 보이는 표시가 없어서, 모드가 바뀌는 순간(시크릿 새 탭 화면, 탭 전환기에서 고른 칸, "새 시크릿 탭"·"시크릿 탭에서 열기" 누름)을 보고 기억한다. 참고로 Chrome은 시크릿 탭에 FLAG_SECURE를 걸어 두어 영상에는 원래 검게 찍힌다 (2026-09-26 실측) |
| 앱 사용 | 어느 앱이 앞에 떠 있었는지, 화면이 켜지고 잠긴 시각을 시스템 UsageEvents에서 읽어 한 시간 조각 JSONL(`app_yyyy-MM-dd_hHH.jsonl`, 소급분은 하루치)로 `LifeRecorder/app`에 업로드. 앱이 죽어 있던 동안 것도 시스템이 들고 있어 되살아난다(며칠치). 설정 > 사용 정보 접근에서 허용해야 한다 |

파일 이름: `audio_2026-09-03_14-00-00.m4a`, `screen_2026-09-03_14-00-00.mp4` (세그먼트 시작 시각).
로컬 저장 위치: `Android/data/com.liferecorder/files/{audio,screen}/`.

산출물의 정확한 형식과 데이터상의 함정은 [`DESIGN.md`](DESIGN.md)에 정리해 두었다.

## 요구사항

- **Android 14 이상** (`minSdk 34`). 그 아래는 포그라운드 서비스 타입 규칙이 달라 동작하지 않는다.
- Android Studio 또는 JDK 17 + Android SDK (`compileSdk 35`).
- 업로드를 쓰려면 Google 계정과 **본인이 만든** Google Cloud 프로젝트.

기준 기기는 **Galaxy Z Flip 5 (One UI, Android 14~16)** 이고, 이 기기에서만 실사용 검증했다.
다른 제조사 기기에서도 원리상 동작하지만 절전 정책이 달라 서비스가 더 쉽게 죽을 수 있다.

**일부 기능은 한국·삼성 환경 전제다.** 없어도 나머지는 정상 동작하며, 앱 안에서 개별로 끌 수 있다.

| 기능 | 전제 |
|---|---|
| 통화 녹음 수집 | 폰이 통화 녹음 파일을 공용 저장소에 남길 것 (삼성 기본 전화, T전화 등). 경로는 `Config.CALL_RECORDING_PATHS`에서 바꾼다 |
| 카카오톡 수집 | 카카오톡(`com.kakao.talk`) 설치. 다른 메신저를 쓰려면 `Config.KAKAO_PACKAGE`를 바꾸면 되지만 알림 구조가 앱마다 달라 파싱은 손봐야 한다 |
| 문자 수집 | SMS/MMS. RCS(채팅)는 시스템이 열어주지 않아 불가능 |
| 화면 글자 읽기 | 설정 > 접근성에서 Life Recorder 켜기. 앱 버전이 바뀌면 뷰 id가 달라질 수 있다 (글자 자체는 그대로 잡힌다) |
| 앱 사용 기록 | 설정 > 사용 정보 접근에서 Life Recorder 허용. 앱 이름을 붙이기 위해 `QUERY_ALL_PACKAGES`를 쓰므로 스토어 배포와는 맞지 않는다 |

마이크 녹음·화면 녹화·Drive 업로드는 **어느 안드로이드 14+ 기기에서든** 그대로 쓸 수 있다.

## 시작하기

### 1. 빌드

```powershell
git clone https://github.com/sehunYang/life-recorder-for-android.git
cd life-recorder-for-android
.\gradlew.bat assembleDebug
```

Android Studio로 열어서 실행해도 된다. `local.properties`는 Android Studio가 만들어 주고,
CLI로만 빌드한다면 SDK 경로를 직접 적는다:

```
sdk.dir=C:/Users/<사용자명>/AppData/Local/Android/Sdk
```

설치:

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

### 2. Google Drive 연결 (업로드를 쓸 경우)

앱은 Play 서비스의 AuthorizationClient를 쓰므로 **코드에 클라이언트 ID를 넣지 않는다.**
대신 각자 자기 프로젝트에 패키지명 + 서명 SHA-1로 Android OAuth 클라이언트를 등록해야 한다.
**여기서 만든 자격증명은 저장소에 들어가지 않는다.**

1. https://console.cloud.google.com 에서 프로젝트 생성
2. **API 및 서비스 > 라이브러리** → `Google Drive API` 사용 설정
3. **OAuth 동의 화면** → 외부(External), 범위에 `https://www.googleapis.com/auth/drive.file` 추가
   - Drive 전체가 아니라 **이 앱이 만든 파일에만** 접근하는 범위다
   - 대상(Audience)에서 테스트 사용자로 본인 계정 추가
   - 테스트 상태는 인증이 약 7일마다 만료될 수 있다. 만료되면 앱이 알림을 띄우고, 한 번 탭해 다시 연결하면 된다
4. **사용자 인증 정보 만들기 > OAuth 클라이언트 ID** → 유형 **Android**
   - 패키지 이름: `com.liferecorder` (직접 바꿨다면 그 값)
   - SHA-1: 빌드하는 PC마다 다르므로 아래로 직접 구한다

```powershell
keytool -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android
```

5. 앱에서 **Google 계정 연결** → 계정 선택 및 Drive 권한 허용

### 3. 폰 설정 (안 죽게)

1. 앱 실행 → **배터리 최적화 제외 요청** 버튼 → 허용
2. (삼성) 설정 > 배터리 > 백그라운드 사용 제한 > **절전 예외 앱**에 추가
3. (삼성) 설정 > 앱 > Life Recorder > 배터리 → **제한 없음**
4. **기록 시작 (ON)** → 마이크/알림 권한 허용 → 화면 캡처 동의 팝업에서 "전체 화면" 시작

**화면 녹화를 밤새 유지하려면 이 설정이 사실상 필수다.** 안 하면 잠금화면이 뜰 때마다
안드로이드가 화면 녹화를 강제 종료한다(`STOP_REASON_KEYGUARD`).

```powershell
adb shell appops set com.liferecorder PROJECT_MEDIA allow
```

설치·테스트 전체 절차는 [`TESTING.md`](TESTING.md)에 단계별로 적어 두었다.

### 4. 홈 화면 위젯 (선택)

홈 화면을 길게 눌러 **위젯 > Life Recorder > 기록 시작·중지**를 2x1 크기로 놓는다.
위젯 전체가 버튼 하나다.

- **꺼짐 → 누르면**: 소리 녹음이 앱을 열지 않고 바로 시작되고, 이어서 화면 캡처 동의 창이 뜬다.
  `PROJECT_MEDIA` appop를 허용해 둔 기기(위 명령)에서는 이 창도 뜨지 않고 곧바로 화면 녹화까지 켜진다.
- **기록 중 → 누르면**: 즉시 전부 중지된다(앱의 OFF 버튼과 같다).
- 마이크·알림 권한이 아직 없으면 위젯에서는 물어볼 수 없으므로 앱이 열린다. 한 번 허용하고 나면 그 뒤로는 위젯만으로 켜고 끌 수 있다.
- 위젯 글씨가 상태를 그대로 보여 준다: `기록 꺼짐 / 눌러서 시작`, `기록 중 / 소리만 · 눌러서 중지`, `기록 중 / 소리 + 화면 · 눌러서 중지`.

## 알아둘 것

- **화면 녹화는 자동 재개가 불가능하다.** Android 14+에서 화면 캡처 동의 토큰이 일회용이라,
  시스템이 서비스를 죽였거나 재부팅되면 알림("화면 녹화가 중단됨 · 탭하여 재개")을 탭해서 다시 동의해야 한다.
  소리 녹음은 서비스가 되살아나면 자동으로 이어진다.
- 재부팅 후에는 Android 15 규칙상 마이크 서비스를 자동으로 못 띄운다. "탭하여 재개" 알림만 뜬다.
- 통화 중이거나 다른 앱이 마이크를 잡으면 그 동안 무음으로 기록된다.
- 화면이 꺼지면 캡처 입력을 끊으므로 영상에는 꺼지기 직전 프레임이 그대로 남는다(용량 거의 0). 앱 화면의 "일시정지: 화면 꺼짐" 표시로 확인 가능.
  기기/OS 버전에 따라 화면 잠금 시 캡처가 시스템에 의해 종료될 수 있으니 한 번 실제로 확인해 볼 것.
- `FLAG_SECURE`를 건 앱(웹툰·은행·OTT 등)은 시스템이 검게 넘긴다. 앱에서 우회할 수 없다.
- WakeLock을 잡지 않으므로, 화면 꺼진 상태에서 몇 시간 뒤에도 녹음이 이어지는지 첫날 확인할 것. 끊기면 `RecordingService`에 PARTIAL_WAKE_LOCK을 되살리면 된다.
- 통화 녹음 경로가 다르면 `Config.CALL_RECORDING_PATHS`에 패턴을 추가하면 된다. 현재는 T전화 폴더가 1순위.
- 문자는 "어제까지"만 만든다. 오늘 문자는 내일 올라간다. 하루가 통째로 담겨야 중간에 끊긴 파일이 안 생기기 때문.
- 문자 읽기는 민감 권한이라 Play 스토어 배포 시 제약이 있지만, 직접 빌드해 설치하는 방식이라 무관하다. 스토어에 올릴 생각이면 이 권한부터 검토할 것.
- **알람 앞뒤로 녹음이 잠시 멈춘다** (v0.8~). 녹음 중이면 알람이 진동·화면만 되고 소리가 안 났다(Flip 5). 켜진 알람 1분 전에 마이크를 놓고, 알람이 끝나 화면이 꺼지거나 잠금을 풀면(늦어도 30분) 다시 녹음한다. 타이머·캘린더 알림 소리는 대상이 아니다.
- 기본값은 충전 중에만 자동 업로드다. 그러면 하루치(대략 3~8GB)를 폰에 들고 있다가 밤에 올린다 — 저장 공간을 확인할 것. 맥이 낮에 바로 반영하게 하려면 설정에서 "충전 중에만"을 끈다 (Wi-Fi 전용은 유지).
- 캡처 해상도는 시작 시점의 메인 화면 크기로 고정된다. Flip 5는 접으면 메인 화면이 꺼질 뿐 크기가 바뀌지 않아 문제없지만,
  커버 화면(외부 화면)은 별도 디스플레이라 녹화되지 않는다.
- 세그먼트 경계는 정각을 1분 간격으로 벽시계 기준 확인하므로, 시계가 보정돼도 최대 1분 안에 따라온다.
- 앱을 완전히 종료(OFF)하면 마지막 세그먼트도 remux되어 업로드 대기열에 들어간다. 앱을 바로 강제 종료하지 말고 몇 초 기다릴 것.
- 프로세스가 강제 종료되면 진행 중이던 화면 녹화 mp4는 복구 불가(삭제됨). 소리는 살아남는다.
- 용량 대략치: 소리 약 70MB/시간, 화면은 정지 화면이 많으면 수십 MB, 계속 조작하면 최대 360MB/시간.
- 품질/비트레이트/해상도는 `Config.kt` 한 곳에서 바꾼다.

## 카카오톡

이 앱은 **모으기만 하고 해석하지 않는다.** 합치고 복원하는 일은 내려받은 raw data를 처리할 때 한다.

**알림 로그** — 카카오톡 알림에 뜬 내용을 한 줄에 JSON 하나씩 그대로 쌓는다.

```
{"t":1788500640000,"room":"홍길동","sender":"홍길동","text":"점심 먹었어?",
 "posted":1788500640500,"style":"messaging","me":"나의 표시 이름","chatLogId":"3923230618582036480"}
```

- `t`는 메시지가 보내진 시각, `posted`는 알림이 뜬 시각이다. 밀린 알림은 둘이 벌어진다.
- `me`는 이 알림을 받은 계정의 카카오톡 표시 이름이다. 듀얼 메신저로 둘을 쓰면 계정마다 다르다.
- `chatLogId`는 카카오톡이 메시지마다 붙이는 고유 번호다. 같은 메시지가 알림에 다시 실려도 이 값은 같아서 중복 제거 키로 쓴다.
- `senderKey`는 **방 안에서만** 같은 사람을 가리킨다. 같은 사람이 다른 방에 있으면 값이 다르다. 카카오톡이 그렇게 주므로 앱에서 고칠 수 없다.
- `style`이 `messaging`이면 카카오톡이 준 구조화된 메시지다. `plain`이면 알림 본문 한 줄에서 뽑은 것이라
  `"메시지 5개"` 같은 요약이거나 내용 표시를 꺼서 온 안내 문구일 수 있다. 앱은 이걸 버리지 않고 표시만 해 둔다.

정각 1분 뒤 지난 한 시간을 `kakao_yyyy-MM-dd_hHH.jsonl`로 확정해 업로드한다 (v0.8~). 지금 시간치는 `rawkakao_...jsonl.part`로 계속 이어 쓰는 중이라 올라가지 않는다.
발화 시각이 같은 중복만 걸러낸다. 그 외에는 손대지 않는다.

### 알림 파싱이 깨지는 조건과 대응

| 조건 | 실제 영향 | 대응 |
|---|---|---|
| 안 읽고 쌓아둬 "메시지 5개"로 접힘 | **거의 없음.** 접히는 건 보여주는 방식일 뿐이고, MessagingStyle 안에는 최근 몇 건이 각각 들어 있다. 새 메시지마다 알림이 다시 떠서 그때마다 최근 묶음이 통째로 다시 온다 | MessagingStyle에서 개별 메시지를 꺼내 쓴다. 같은 게 또 와도 발화 시각으로 걸러진다 |
| 카카오톡에서 "메시지 내용 표시" 끔 | **치명적.** 본문 대신 안내 문구만 온다. 앱에서 막을 방법이 없다 | `style:"plain"`으로 남아 내려받은 뒤 구분할 수 있다. **카카오톡 설정 > 알림에서 내용 표시를 켜 둘 것** |
| 알림 끈 대화방 | **통째로 안 들어옴.** 앱에서 막을 방법이 없다 | 화면 녹화 영상에는 남으므로 처리 단계에서 메운다 |
| 과거 대화를 스크롤해 올림 | **알림에는 영향 없음.** 스크롤은 알림을 만들지 않는다. 화면 OCR을 할 때 생기는 문제이고, 그 처리는 이 앱 밖이다 | 처리 단계에서 발화 시각으로 걸러야 한다 |

그 외에 놓치는 경우: 내가 보낸 메시지(알림이 없음), 채팅방을 열어둔 동안 받은 메시지(알림이 안 뜸),
방해 금지 시간대. 모두 화면 녹화 영상에는 남고, 앞의 둘은 **화면에서 읽기(아래)** 를 켜면 글자로도 남는다.

앱이 죽었다 살아나거나 시스템이 연결을 끊는 경우에 대비해, 연결되는 순간 알림창에 이미 떠 있는 것들을 먼저 훑고,
끊기면 다시 붙여달라고 요청한다.

### 알림에서 실제로 무엇이 오는지 확인하는 법 (진단 덤프)

카카오톡이 알림에 무엇을 담아 보내는지는 기기와 카카오톡 버전에 따라 다르므로 실제로 찍어봐야 안다.
앱의 카카오톡 카드에서 **진단: 알림 원본 덤프**를 켜면, 알림 하나하나를 통째로 남긴다.

- 파일: `kakao/kakao_dump_<날짜>.jsonl` — 다른 파일과 같이 `LifeRecorder/kakao`로 업로드된다
- 실시간으로 보려면: `adb logcat -s KakaoDump` (긴 줄은 잘리므로 원본은 파일 쪽을 볼 것)

덤프 한 줄에 들어가는 것:

| 키 | 내용 |
|---|---|
| `sbn` | key, id, tag, groupKey, postTime 등 알림 자체의 식별값 |
| `notification` | flags, category, channelId, group, sortKey, **shortcutId**, when, number |
| `extras` | 알림 extras 번들 **전체**. `android.messages`, `android.messages.historic` 배열이 여기 원본 그대로 들어 있다 |
| `messagingStyle` | 우리가 읽는 경로가 돌려주는 값. `messageCount`, `historicCount`, 각 메시지의 `personIsNull`, `dataMimeType`, `dataUri` |

확인 절차: 덤프를 켠 뒤 대상 대화방에서 **내가 한 건 보내고**, 상대에게 한 건 받고,
사진·이모티콘·삭제된 메시지를 각각 한 번씩 주고받은 다음 파일을 열어보면 된다.
카카오톡을 **화면에 띄워둔 채로** 메시지를 받아보면 그 동안 알림이 올라오는지도 같이 확인된다.

### 화면에서 읽기 (접근성)

알림은 상대 발화만 준다. 내 발화, 방을 열어 둔 동안 받은 메시지, 그룹방 이름은 **화면에는 있다.**
접근성 서비스는 화면의 뷰 계층을 글자로 주므로, OCR 없이 원문 그대로 남는다.
카카오톡만이 아니라 **앞에 떠 있는 모든 앱**을 읽는다 (함께 모으기 카드의 "화면 글자 읽기").

- **접근성 설정 열기** → 설치된 앱 > Life Recorder 켜기
- 앞에 떠 있는 앱만 읽는다. 카카오톡이 뒤에 있으면 카카오톡 줄은 안 생긴다. 알림 로그와 서로 보완한다
- 화면이 바뀔 때마다 **새로 나타난 글자만** 한 줄로 남긴다. 각 글자에 화면 좌표가 붙어 있어 말풍선이 왼쪽(상대)인지 오른쪽(나)인지 내려받은 뒤 가릴 수 있다
- 채팅방 창 제목이 곧 방 이름이다. 알림에 없던 그룹방 이름이 여기서 나온다
- 타자 치는 중인 입력창은 남기지 않고, 타자를 멈췄을 때 잡는다. 비밀번호 입력란은 어느 앱이든 남기지 않는다
- **삼성 인터넷의 웹 본문은 오지 않는다** (주소창·탭 제목만). 삼성 인터넷이 접근성에 웹 내용을 내놓지 않아서다. 게임·영상처럼 그림으로 그리는 화면도 글자가 없다. 그런 것은 화면 녹화에만 남는다
- 파일: `screentext_yyyy-MM-dd.jsonl` → `LifeRecorder/screen-text`. 형식은 `DESIGN.md` 3.10

**대화 내보내기 파일** — 카카오톡에서 채팅방 > 메뉴 > 대화 내용 > 내보내기 후 Life Recorder로 공유하면
그 파일을 변환 없이 `kakao_<시각>_export_<원본이름>` 으로 올린다.
앱의 카카오톡 카드에 가져오기 버튼이 둘 있다.

- **파일 고르기** — 텍스트만 내보낸 `.txt`나 `.zip`을 고른다
- **폴더 고르기** — "미디어 포함 저장"이 `Documents/KakaoTalk/Chats/<대화방>/`에 만든 폴더를 통째로 가져온다.
  대화록은 `LifeRecorder/kakao`로, 사진·동영상은 `LifeRecorder/kakao-media`로 나눠 올린다 (`kakaoexp_` 접두어).
  사진이 많아 하나씩 고를 수 없을 때 쓴다

내보내기 결과가 카카오톡 버전에 따라 txt 한 개, zip 한 개, 여러 파일, 또는 첨부 없는 본문 텍스트로
제각각 나오기 때문에 공유 필터를 타입으로 좁히지 않았다. 그래서 Life Recorder는 카카오톡뿐 아니라
**모든 공유 목록에 뜬다.** 무엇을 보내든 변환 없이 그대로 `kakao` 폴더에 올라간다.

알림 로그를 쓰려면 설정 > 알림 > 알림 접근에서 Life Recorder를 켜야 한다.
앱의 카카오톡 카드에 그 설정을 여는 버튼이 있다.
